# 01. 비즈니스 분석 문서 재현성 보강

> [PRD-From-VPS-Sample](https://github.com/wild-mental/PRD-From-VPS-Sample/blob/main/00_Prompt-History/01_Refining%20Business%20Analysis%20Documentation.md)의 1번 프롬프트 이력에 대응. 우리 저장소에서는 **분석 결과물이 방법론 문서와 어긋나 있다는 것을 발견하고 재현 가능한 출력 포맷을 방법론에 역으로 반영**한 실제 프롬프트를 기록한다.

## 실제 프롬프트 (챕터 02 가치사슬, 그대로 인용)

> "분석방법론 문서에 분석결과 중 지금 전체 가치사슬 개요 부분도 만들어야 한다는 내용은 언급된 적이 없었네? 분석 방법론 문서를 다음에 사용했을 때에도 현재 만들어진 분석 결과물 포맷과 같이 충실한 결과물을 받을 수 있도록 재현 가능한 형태의 아웃풋 포맷 지시문을 보강해줘."

## 무엇이 일어났는가

- 산출물(분석 결과 마크다운)이 이미 방법론 문서보다 더 충실했다는 것을 사용자가 먼저 발견했다.
- 방법론 문서에 **"## 4. 출력 포맷"** 절을 신설해 종합판단표·산업매력도판단·본문 서술규칙·파일명규칙을 명시했다.
- 사용자가 "ㅇㅇ"로 동일한 보강을 [챕터 01 Porter's 방법론](../01-porters-five-forces/분석-방법론.md)에도 적용하도록 확인했다.

## 이 실습에서 얻은 교훈

**방법론 문서는 결과물을 보고 나서 역으로 검증·보강해야 한다.** 먼저 결과물을 만들고, 그 결과물이 우연이 아니라 재현 가능하다는 것을 방법론에 박아 넣는 순서가, 방법론부터 완벽하게 쓰고 결과물을 만드는 것보다 실제로 더 잘 작동했다.
