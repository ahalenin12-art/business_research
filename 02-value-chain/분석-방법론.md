# 02 - 기업 내부 활동의 가치 사슬 분석

> 본 챕터의 분석은 이 문서에 정의된 방법론을 따른다.
> 질문표는 **특정 산업에 종속되지 않도록** 작성되어, 제조·서비스·플랫폼·유통 등 어떤 도메인에도 그대로 대입할 수 있다.

## 3. 사용 안내

- 위 질문표는 **모든 산업에 공통으로 적용 가능한 형태**로 작성되어 있다. 실제 분석에서는 각 질문의 추상적 표현을 그 산업의 구체적 언어로 바꿔 답한다.
  - 예 · 제조업 — *"핵심 투입자원"* → 원자재·부품 / *"검수·표준화"* → 입고 검사·규격 관리
  - 예 · 플랫폼 — *"핵심 투입자원"* → 사용자 생성 콘텐츠·데이터 / *"검수·표준화"* → 모더레이션·메타데이터 정규화
  - 예 · 금융 — *"핵심 투입자원"* → 고객 동의 기반 금융데이터 / *"검수·표준화"* → 데이터 정제·마이데이터 표준화
- **설계 🏗️** 질문은 아직 활동이 없는 상태에서 *무엇을 만들 것인가* 를 정할 때, **개선 🚀** 질문은 이미 돌아가는 활동에서 *어디를 고칠 것인가* 를 찾을 때 쓴다.
- 9개 활동을 모두 같은 깊이로 분석할 필요는 없다. 해당 산업에서 **원가 비중이 크거나 차별화가 일어나는 활동**에 분석을 집중한다.

## 4. 출력 포맷 (재현성을 위한 지시문)

> 이 방법론으로 분석을 수행할 때 산출물은 아래 구조를 그대로 따른다. 목적은 **분석 대상(산업·기업)이 바뀌어도 항상 같은 깊이와 형식의 결과물**이 나오도록 하는 것이다. 질문표(1·2절)가 "무엇을 물을 것인가"를 정한다면, 이 절은 "그 답을 어떤 문서 구조에 담을 것인가"를 정한다.

### 4-1. 개별 분석 파일 구조

1. **머리말**: `# 가치사슬 분석: {분석 대상}` 제목과, blockquote로 분석 대상 범위·기준일·`분석-방법론.md` 링크(및 존재한다면 다른 챕터의 관련 분석 링크)를 명시한다.
2. **종합 요약 표 (필수, 본문 최상단)**: 9개 활동(주요활동 5 + 지원활동 4) 전체를 담은 표를 반드시 넣는다. 열은 `활동 | 원가 비중·차별화 여부 | 한 줄 진단` 3열로 고정하고, 가운데 열에는 "원가 비중 큼/작음", "차별화 핵심/차별화 약함", "진입장벽", "리스크 핵심" 중 해당하는 표현을 사용한다.
3. **핵심 진단 (필수)**: 종합 요약 표 바로 아래에 3~5문장의 문단을 둔다. 활동을 하나씩 나열하지 말고 **"가치사슬 전체에서 병목이 어디에 있는가"를 한 문장으로 압축**해 제시한다.
4. **본문 서술**: 방법론의 대분류(`## 1. 주요활동` / `## 2. 지원활동`)를 그대로 사용하고, 9개 활동을 `### 1)`~`### 9)` 소제목(활동명 + 짧은 캐치프레이즈)으로 구성한다.
   - 질문표의 질문에 하나씩 순서대로 답하지 말고, 질문을 참고삼아 **그 산업의 구체적 사실(수치·기업명·계약구조·사례)**로 bullet를 채운다. 추상적 질문 문장을 그대로 복사하지 않는다.
   - 확인되지 않아 업계 관행으로 추정한 내용은 문장 안에서 "~로 추정된다/추론"처럼 즉시 표시한다.
   - 가능하면 활동마다 **"함의" 또는 이에 준하는 문장**을 두어, 같은 대상에 대한 다른 챕터(예: 포터의 5가지 힘) 분석과 상호 링크로 연결한다.
5. **참고 출처**: 파일 하단에 마크다운 링크 목록으로 정리한다.
6. **자료 신뢰도 참고**: 마지막 인용구(`>`)로, 공개 자료로 확인되지 않아 추정한 항목이 무엇인지 명시한다.

### 4-2. 비교 분석 파일 구조

두 개 이상의 분석 대상을 다뤘다면 비교 파일을 별도 문서로 작성하며, 아래 구조를 따른다.

1. **활동별 비교표**: 9개 활동 × 대상별 요약 × "병목이 더 심한 쪽" 판정을 한 표에 담는다.
2. **핵심 차이**: 각 대상이 가치사슬의 어느 지점(입구/중간/출구)에서 병목이 걸리는지 서술형으로 대비하고, 두 대상이 공유하는 공통 패턴을 별도 소제목으로 짚는다.
3. **구조도 (mermaid)**: 각 대상의 활동 흐름과 병목 지점을 시각적으로 표시한다.
4. **전략적 시사점**: 번호가 매겨진 목록으로 실행 가능한 판단(자원을 어디에 집중할지, 어떤 리스크를 우선 관리할지 등)을 제시하고, 마지막 항목에는 다른 챕터(다른 프레임워크)의 비교 분석과의 연결점을 넣는다.
